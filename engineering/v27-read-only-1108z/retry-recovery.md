# Read-only turn recovery
The public read-only pipeline requires two physical provider requests: selection/draft, then grounded answer/independent review. It does not persist an intermediate model response for cross-request continuation. After a generation has started provider work, a full restart cannot fit the original durable two-call allowance. Previously HTTP 500 on either phase and an already-exhausted durable turn all returned TEMPORARY_PROVIDER_FAILURE, inviting a futile same-turn Try again.

Actual public POST regression tests reproduced those three incorrect recovery codes before the fix (five other cases passed). The route now returns ANSWER_NOT_COMPLETED, retryable false, after started generation work or durable admission exhaustion. The UI preserves the question through its existing Edit question action. A new submission is an explicit user-reviewed new logical turn. No call counter, deadline, cost or credit authority is reset server-side. Zero-call infrastructure refusal still invites safe same-turn retry. Completed-answer GET recovery and lost-acknowledgment persistence recovery are unchanged. No third model request is added. Provider HTTP 500, timeout and malformed output are simulated offline; they are not claimed as induced live provider failures.

Seven old source-shape contracts required public mutation executors, mutation invalidation or the retired generation function. The same 38-case test set reproduced seven failures before migration and passed all 38 after migration to the actual read-only route and terminal persistence functions. Unaffected navigation guards, canonical request identity, existing non-AI freshness observers, SQL/RLS, immutable credit and historical suggestion SQL assertions remain. No tests were deleted, skipped or excluded from unfiltered full CI. Full CI remains a release gate.
