# Mixed-request completion

Owner observations, saves, historical reads, calculations and general guidance have separate authority. An observation's date cannot constrain an independent historical lookup. For mixed past/current requests, the read envelope is compiled from the grounded historical evidence facets and still clipped by the subscription access window.

Explicit note saving runs before interpretation. An embedded question using “if” no longer cancels an independent affirmative save; conditional saves, opt-outs, ambiguous subjects and multi-record changes keep their existing authorization requirements. Writer, reviewer and repair all receive the server's completed-note receipt. The receipt satisfies only that exact save and never verifies a clinical interpretation.

Whole-answer review still requires all obligations and actions to pass. In the same bounded provider call, the reviewer separately marks self-contained, source-supported chunks suitable for partial delivery. Those flags cannot approve task completion or mutations. The server checks source bindings, numeric/date anchors, publication rules and unchanged review identity before retaining any selected chunks. An invalid selected chunk is excluded; separately approved self-contained chunks can remain. No partial set certifies task completion. Failed repair may preserve independently verified prose from the original or repaired draft, but never unreviewed prose or a rejection explanation.

Partial prose is explicitly labeled incomplete. Structured outputs retain their full-format review requirement. Source-only fallback no longer echoes mixed instructions as owner observations. Failed completion releases the Ask credit for mixed requests as well as read-only requests. A confirmed raw note remains saved independently.

Regression coverage includes conditional versus independent commands, separate historical/current dates, confirmed receipts during historical review, whole-task rejection with useful guidance, unsupported numerical anchors, and receipt invalidation after source changes or cloning.

Prompt trimming protects the last owned in-window candidate matching a requested quantity before generic recency candidates. A literal match only changes retrieval priority, never semantic support or source authority. Deterministic prose anchor failures use bounded chunk repair; generic reminders about action claims do not force regeneration of the complete answer schema.

A completed raw-note receipt disables duplicate event, learning and recovery extraction in every answer generation or repair result. The durable enrichment worker owns that optional work. Immediate safety evaluation and final answer validation remain active. This prevents optional extraction rejection from discarding a requested companion answer.
